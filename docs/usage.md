## Основные команды

| Клавиши / команда | Действие |
| --- | --- |
| Ctrl+p / Ctrl+f | Файлы / поиск по проекту |
| Ctrl+b | Дерево файлов |
| Space fb / bd / bo | Буферы / закрыть / закрыть остальные сохранённые |
| gd / gr / K | Определение / ссылки / документация |
| Space rn / ca / cf | Переименование / code action / форматирование |
| Space ci | Подсказки типов |
| Space xx / xd | Диагностика проекта / текущей строки |
| Space gg | Git |
| Space sr | Поиск и замена в проекте |
| Space qs / qS | Восстановить сессию / выбрать сессию |
| Space tp / `:ProjectTask` | Cargo или скрипты package.json из корня проекта |
| Space tr / tt | Задачи Overseer / список задач |
| Space tg | Терминал |
| Space uz | Режим сосредоточенного письма |
| Space uh / `:checkhealth config` | Зависимости конфигурации |
| `:LspRefresh` | Подключить недавно установленные серверы |

Верхняя панель показывает **буферы файлов**. Shift+L / Shift+H переходят
к следующему / предыдущему буферу в видимом порядке, с переходом через край.
Новые буферы добавляются в конец. Клик выбирает соответствующий буфер;
закрытие текущего выбирает соседа справа, а у правого края — соседа слева.
Переключение не зависит от последней перерисовки панели.

`gt` / `gT` переключают отдельные вкладки Neovim, созданные через `:tabnew`.
Это отдельный список рабочих пространств; Shift+H / Shift+L сохраняют
текущую вкладку и меняют только её буфер.

`ProjectTask` показывает реальные npm-скрипты, включая `dev`, `build`, `check`,
если они есть в проекте. Менеджер пакетов определяется по `packageManager`
или lockfile. Уже работающая задача открывает существующий терминал;
остановка — Ctrl+c в нём. Несохранённые изменения команда не записывает.

Изменение размера окна сохраняет текущую вкладку. После `:q`, `:wq`, `:x` или `ZZ` сохранённый буфер закрытого окна
удаляется из панели, если он больше нигде не показан. Отменённый выход
не удаляет буфер; `:q!` сохраняет штатную семантику принудительного выхода. Установка LSP через Mason подхватывается автоматически. Для ручной установки
вне Mason достаточно входа в буфер, возврата фокуса или `:LspRefresh`. Изменения Lua-конфигурации требуют
одного перезапуска; палитра обновляется через `:lua require("theme").reload()`.

Обычные `d`/`dd`/`D`, `x`, `c` и `s`, включая удаление выделения,
не меняют регистры вставки и системный буфер обмена. Копирование — `y`/`yy`.
Явные именованные регистры, например `"ad`, сохраняют обычное поведение.
Повтор через `.` и отмена через `u` работают как обычно.

Панель показывает только обычные файловые буферы и скрывается, когда их меньше
двух. Закрытие обновляет и изображение панели, и список переходов, даже когда
сама панель скрыта. Служебные буферы не включают её обратно.

## Rust и Python

Rust: rustaceanvim, rust-analyzer, Clippy, Cargo completion и отладка codelldb.
Mason-версия rust-analyzer имеет приоритет перед rustup proxy. Пустой Cargo.toml
порождает одно предупреждение; после исправления используйте `:RustAnalyzer start`.
`ProjectTask` предлагает `cargo check`, `clippy`, `test`, `bench` и `run`.

| Клавиши | Действие |
| --- | --- |
| Space rr / rt / rd | Rust runnable / тест / отладка |
| Space re / rD / rc | Макрос / docs.rs / Cargo.toml |
| Space rR | Перезапустить rust-analyzer |
| Space pi / pv | Python: окружение / выбрать интерпретатор |
| Space pr | Сохранить и запустить Python-файл |
| Space pf / po / pF | Ruff format / imports / форматирование при сохранении |
| F5 / F9 / F10 / F11 / Shift+F5 | Отладка / breakpoint / over / into / stop |
| Space tT / tF / tA / tD | Тест рядом / файл / проект / отладка теста |
| Space ts / to / tx | Панель тестов / вывод / остановка |

Python использует Pyright для типов и Ruff для линтинга и форматирования.
Приоритет интерпретатора: выбор для проекта → `.venv`/`venv`/`env` проекта →
активное Virtualenv/Conda → Python из PATH. Выбор действует в текущей сессии.
Тесты запускаются из корня проекта и требуют pytest в выбранном окружении;
асинхронные тесты также требуют pytest-asyncio.

Python форматируется при сохранении; файлы свыше 10 000 строк пропускаются.
`vim.g.disable_autoformat = true` отключает это глобально. Отладчик загружает
`.env` из корня проекта; обычный запуск и тесты сами управляют окружением.

Сниппеты: `amain`, `adef`, `atest`, `amock`, `afix`, `logger`, `experiment`.
Последний создаёт каркас эксперимента с аргументами `--seed` и `--output`,
таймером и JSON-метриками; место настоящей метрики нужно заполнить самостоятельно.
Seed управляет только локальным генератором Python, не NumPy/PyTorch.
Tab раскрывает сниппет под курсором и переключает поля активного сниппета,
Shift+Tab возвращает назад. За пределами сниппета Tab вставляет обычный отступ;
старые поля на другой строке или перед курсором не перехватывают клавишу.
Ctrl+Space открывает completion, Ctrl+y принимает результат.

## LaTeX и Markdown

VimTeX управляет сборкой XeLaTeX/latexmk и просмотром PDF через Zathura.
Texlab отвечает за LSP. Параметры проекта и `% !TeX program` сохраняют приоритет.
Выходные файлы находятся в `build/`. Для отдельных глав задавайте `% !TeX root`.
Сохранение `.tex`/`.ltx` запускает сборку, если continuous-компилятор ещё не работает.

| Клавиши | Действие |
| --- | --- |
| Space ll / lL / lk | Continuous build / собрать один раз / остановить |
| Space la | Сборка при сохранении в текущем буфере |
| Space lv / le / lo | PDF / ошибки / журнал сборки |
| Space lt / li / ls | Оглавление / проект / статус |
| Space lm / lz | Исходный TeX или conceal / режим письма |
| Space wn / `:NoteTemplate` | Новая заметка по шаблону |
| Space wc / `:WritingStats` | Слова, символы и приблизительное время речи |
| `:Glow` | Предпросмотр Markdown в терминале |

`NoteTemplate research`, `proof`, `video`, `stream` создают несохранённый
Markdown-буфер: исследование с источниками и воспроизводимостью, доказательство,
видеосценарий или план эфира. Сохранение — обычное `:w путь.md`.
Время речи оценивается по 150 словам в минуту.

В Markdown доступны рендеринг таблиц и чек-листов, Marksman и форматирование.
Блоки кода имеют тёмный фон по ширине содержимого, без сплошных полос.
Орфография по умолчанию выключена; Space us включает её в текущем окне.
Язык проверки задаётся через `:setlocal spelllang=...`; для русского нужен
установленный словарь `ru`.
LaTeX-сниппеты: `xedoc`, `beg`, `eqn`, `align`, `dm`, `mm`, `frac`, `sum`, `int`,
`fig`, `tbl`, `theorem`, `proof`, `ref`, `cite`, `sec`, `ssec`, `pkg`, `cmd`, `expl`.
Сниппет `xedoc` требует указанные в нём шрифты и TeX-пакеты.

## HTML, Astro и TypeScript

Astro LSP, TypeScript LSP, HTML/CSS, Emmet и Tailwind подключаются по типу файла.
ESLint работает через LSP.
Prettier предпочитает установленную в проекте версию. Для Astro установите
в проекте `prettier` и `prettier-plugin-astro` и укажите плагин в конфигурации
Prettier. Mason-копия плагина используется как запасной вариант, если доступна.
MDX форматируется через Prettier.

Настройка Astro сверена с [официальной документацией](https://docs.astro.build/en/editor-setup/).
Запуск dev-сервера: Space tp → `dev`, если такой скрипт есть в package.json.

## Исследования

Molten: Space ni — выбрать kernel, nl — строка, ne в visual mode — выделение,
nr — повторить ячейку, no — вывод, nx — прервать, nq — завершить kernel.
Для работы нужны Python provider (`pynvim`), `jupyter_client`, Jupyter и
зарегистрированный kernel нужного окружения, например с ipykernel.
Проверка: `:checkhealth vim.provider`. Выбор Pyright-интерпретатора не переключает
Jupyter kernel — его выбирают отдельно через MoltenInit.

Space uv включает таблицы CSV. Просмотр изображений требует Kitty и ImageMagick
(`magick`). Доступны Java/JDTLS и отладка нативного кода.
